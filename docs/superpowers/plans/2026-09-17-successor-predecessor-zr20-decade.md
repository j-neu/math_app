# successor_zr20_decade + predecessor_zr20_decade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `successor_zr20_decade` and `predecessor_zr20_decade` (BUILD_ORDER.md Batch 1.3, constructs `successor`/`predecessor`) playable — like Batch 1.2, this is pure spec-authoring: the existing generic `sequence_gap` template with `length: 2` degenerates exactly to "one number shown, one blank for its neighbour," so no new widget or generator code is written.

**Architecture:** Two skill spec JSONs, each 3 levels (enaktiv/ikonisch/symbolisch), both using `template: "sequence_gap"` with `direction: "up"`, `step: 1`, `length: 2`. `successor_zr20_decade` puts the gap at index 1 (`values = [given, given+1]`, child sees `given, _` and types the successor). `predecessor_zr20_decade` puts the gap at index 0 (`values = [given-1, given]`, child sees `_, given` and types the predecessor). Difficulty is driven not by range width (both skills only ever show 2 numbers) but by how close the *given* number sits to a decade boundary: level 1 sits comfortably mid-decade (2-7), level 2 sits at the first boundary (9-10), level 3 sits at the harder, range-edge boundary (18-19, crossing to 20) — mirroring the retired `what_comes_next_exercise.dart`'s L3/L5 "at the boundary is harder" framing and the design doc's own level split ("away from a boundary" -> "exactly at a decade boundary").

**Tech Stack:** Flutter/Dart (`math_app/`), the v4 skill-spec JSON pipeline (`SkillSpec`, `SkillSpecStore`, the existing, unmodified `_generateSequenceGap` and `SequenceGapWidget`), Python sync/coverage scripts.

**Spec:** `docs/clean-room/v4/skills/BUILD_ORDER.md` Batch 1.3 (lines 30-33) + `docs/superpowers/specs/2026-09-15-exercise-plan-design.md` (successor_zr20_decade/predecessor_zr20_decade entries: "Levels: 1) Away from a boundary -> 2) Exactly at a decade boundary (after 10, after 19->20)" / "(before 10, before 20)") + `docs/skill_spec_authoring_guide.md`. Precedent: `docs/superpowers/plans/2026-09-17-count-forward-zr20-zr100.md` (Batch 1.2, the first real `sequence_gap` usage and the spec-JSON shape this plan copies).

## Global Constraints

- German UI only — every user-facing string (`prompt_de`, `level_titles_de`) is German.
- Every generated value stays in `[1, 20]` (ZR20). With `length: 2`, `direction: "up"`, `step: 1`, the max value is `start + 1`; the chosen `start_range` upper bounds (7, 10, 19) keep `start+1 <= 20` in every level.
- The old widget this reuses, `math_app/lib/exercises/what_comes_next_exercise.dart` (C4.1), is still live and wired into `exercise_service.dart` — it is the source to port the mechanic from, not dead code, and this plan does not touch it.
- `sequence_gap`'s evaluation (`_evaluateJoined`, `template_evaluator.dart`) and its only error codes for a single-gap problem — `"miscount"` and the mandatory `"other"` fallback — are unchanged; `"wrong_direction"` does not apply (it only fires for `numberline_step`, and even there only when `expected` has more than one value, which a single ±1 answer never does).
- Never hand-edit `math_app/assets/skill_specs/*.json` — it is generated by `scripts/sync_skill_specs.py`.
- `domain` is `"A"` (Zahlbegriff, "Sequencing forward/backward" subsection), matching `count_forward_zr20`/`count_forward_zr100`.
- `problem_count: 8` / `mastery.correct_of: 8` per level, matching every prior v4 spec.
