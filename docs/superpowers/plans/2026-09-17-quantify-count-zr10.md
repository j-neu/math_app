# quantify_count_zr10 (BUILD_ORDER Batch 1.1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `quantify_count_zr10` (BUILD_ORDER.md Batch 1.1, the first unshipped Tier-1 "Reused" skill) playable — a new "loose dot/plättchen field, tap-to-count" custom widget across all 3 EIS levels, ported from the retired `CountDotsExerciseV2`'s tap-to-count and eye-tracking-scatter mechanics, following the pattern `double_zr10`/`halve_zr10` already proved.

**Architecture:** One skill spec JSON drives 3 levels, each a `custom_widget` (`count_field_enaktiv` / `count_field_ikonisch` / `count_field_symbolisch`) that renders `display.count` loose dots — structured rows (level 1), scattered (level 2), scattered with mixed sizes (level 3, per BUILD_ORDER's own phrasing) — and lets the child tap each dot as a counting aid while typing the total into the shared `BigAnswerField`. Correctness is a plain string match against `expected`, so no new evaluator code is needed. A single generator function (`_generateCountField`) serves all 3 registry keys, mirroring how `_generateDoublingMirror`/`_generateHalvingMirror` each serve their own 3 keys.

**Tech Stack:** Flutter/Dart (`math_app/`), the v4 skill-spec JSON pipeline (`SkillSpec`, `SkillSpecStore`, `problem_generators.dart`, `template_registry.dart`, `template_evaluator.dart`), Python sync/coverage scripts.

**Spec:** `docs/clean-room/v4/skills/BUILD_ORDER.md` Batch 1.1 + `docs/skill_spec_authoring_guide.md` + `docs/superpowers/specs/2026-09-15-exercise-plan-design.md` §5. Precedent: `docs/superpowers/plans/2026-09-15-exercise-plan-foundation.md` Tasks 4–5 (`double_zr10`, `halve_zr10`).

## Global Constraints

- German UI only — every user-facing string (`prompt_de`, `level_titles_de`, semantics labels) is German.
- The skill is capped at ZR10 (`quantify_count_zr10` — "Mengen zählen bis 10"): every generated `count` must be in `[1, 10]`.
- No wall-clock time or platform randomness anywhere in `problem_generators.dart` — the same `(spec, level, seed)` must always produce the same problem list (`docs/superpowers/plans/2026-09-15-exercise-plan-foundation.md` precedent, enforced by existing determinism tests).
- All interactive tap targets ≥ 44×44 px (child-development accessibility floor established in the §3a gate rounds, see `STATUS.md` "Shipped" §3a entries).
- Only use `error_taxonomy` codes `TemplateEvaluator._candidateErrorCode` can actually emit for this widget family: the undirected `"miscount"` plus the mandatory `"other"` fallback — never a directional `off_by_one_*` code (the exact mistake `double_zr10`/`halve_zr10` shipped with and had to fix, per the authoring guide).
- Never hand-edit `math_app/assets/skill_specs/*.json` — it is generated by `scripts/sync_skill_specs.py` from `docs/clean-room/v4/skills/specs/`.
- Follow `DIFFICULTY_CURVE.md`'s standard curve for counting (Trivial 3–5, Easy 6–8, Medium 10–12, clamped here to the ZR10 ceiling) when choosing each level's `count_range`.

- [ ] **Step 3: Write the generator function**

Add to `math_app/lib/practice/problem_generators.dart`, after `_generateHalvingMirror` (end of file, following the existing doc-comment style):

```dart
/// Registry keys `"count_field_enaktiv"`, `"count_field_ikonisch"`,
/// `"count_field_symbolisch"` (quantify_count_zr10, alle drei Level
/// derselben Skill-Spec, BUILD_ORDER.md Batch 1.1): the widget shows
/// `display.count` loose dots the child taps while counting; the typed
/// total is a plain string match against `expected`, handled by
/// `_evaluateCustomWidget`'s default branch. `count_range` is clamped to
/// `[1, 10]` -- the skill's own ZR10 cap.
Problem _generateCountField(
  SkillSpec spec,
  LevelSpec level,
  int levelNumber,
  int seed,
  int index,
  SeededGenerator gen,
) {
  final countRange = level.intListParam('count_range');
  final lo = countRange.isEmpty ? 3 : max(countRange[0], 1);
  final hi = countRange.isEmpty ? 10 : min(countRange[1], 10);
  if (lo > hi) {
    throw SpecFormatException(
      'count_field: count_range [$lo, $hi] must be within [1, 10] for ZR10',
    );
  }
  final count = gen.nextIntInRange(lo, hi);

  return Problem(
    template: 'custom_widget',
    skillId: spec.skillId,
    level: levelNumber,
    seed: seed,
    index: index,
    promptDe: level.promptDe,
    display: {
      'custom_widget': level.customWidget,
      'count': count,
    },
    expected: [count.toString()],
  );
}
```
