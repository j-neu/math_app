# P4 Teacher Console — Independent Critic Report

**Date:** 2026-09-01
**Critic scope:** running app at http://localhost:3000 (dev, live Supabase `zzxqeqwffexythqzjkxr`) + code listed in the brief + backend edge function `learning-path/index.ts`.
**Method:** logged in as a freshly seeded e2e teacher (via `e2e/seed-fixture.mjs`), exercised every console action in-browser, reloaded to confirm server-side persistence, swept 1280×800 / 1024×768 / 390×844, measured layout/tap-targets/font-sizes programmatically, and read the console.

---

## 1. THE SINGLE BIGGEST REMAINING GAP

**A student's non-latest learning paths are unreachable from the UI:** the class overview links only the single "latest" path per student, the student detail page has no path link at all (`getStudentOverviewLink` is dead code), so a second draft/archived path — exactly the case `pathB` in the seed creates — can only be opened by typing its URL, and the plan's own e2e spec has to `page.goto()` path B directly because the UI cannot navigate there.

## 3. What I could and could not inspect

**Inspected (live, real data):** login → class page Lernpfade section (badge "Entwurf", counts "0 gemeistert · 3 verfügbar", labelled slow chip, real "Stand:" date) → console: draft visibility banner, item order, state badges, per-skill level detail (Stufe 1 "8 Versuche, 7 richtig" + slow chip, Stufe 2 "Noch nicht bearbeitet" as real absence, Stufe 3 "5 Versuche, 4 richtig"), then **activate** (confirm → badge "Aktiv", banner gone, persisted after reload), **set_unlock_width** (3→2, persisted), **reorder** (moved last item up, persisted after reload), **skip** (confirm "Als übersprungen markieren?" → badge "Übersprungen"), **reset** (two-step confirm, skill_progress deleted — slow chip disappeared — first 2 items re-opened, persisted), **archive** (confirm → badge "Archiviert", banner back), **second activate 409** (backend message + hint verbatim, German), **client-side unlock_width validation** (11 → "Bitte gib eine ganze Zahl zwischen 1 und 10 ein.", no backend call), **add skill** (excluded existing skills from picker; added item marked "Hinzugefügt", locked, then one-click "Freischalten" → "Freigeschaltet"). Viewports 1280×800, 1024×768 and 390×844 swept for overflow (none) and clipped German text (none in the P4 section); tap-target and font-size measurements taken programmatically; browser console read at each step; backend code verified (child GET returns `status = 'active'` only, so the draft-until-active rule holds server-side; write paths go through the PATCH function with the teacher JWT; no direct PostgREST writes in P4 components).

**Could NOT inspect:** the child app's view of the path (no student token minted — child-side draft invisibility verified only by code reading of the GET handler, not by an end-to-end child login); runtime rendering of `error.tsx` and `loading.tsx` (requires route interception; code-reviewed only); the class-page empty state at runtime (seeded classes always have a path; code-reviewed); a real no-progress "Stufe 2: Noch nicht bearbeitet" screenshot (verified via accessibility snapshot); dark mode (the dashboard has none); measured contrast ratios (estimated acceptable from Tailwind palette but not instrumented); whether the 409 console error is silenced in production builds.

---

## 4. Verdict

The core loop *Klasse → Lernpfad → aktivieren → Fortschritt* is completable end-to-end with real data, all six required actions work and persist, every visible string is German, every destructive action is confirmed with outcome-stating German text, and the 409 surfaces verbatim. But finding #1 (unreachable non-latest paths) breaks a core requirement (#2: per-student console for *a* path implies the teacher can get to *the* path that needs review), and findings #2/#4/#5 fail the §6 visual gate (44px/14px) on the phone viewport. Not sign-offable until #1, #2 and the visual-gate items are addressed.
