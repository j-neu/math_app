# skip2_forward_zr100 + skip2_backward_zr100 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `skip2_forward_zr100` and `skip2_backward_zr100` (BUILD_ORDER.md Batch 1.4, sub-batch 1.4b's proving pair) playable, and in doing so build the reusable Hundertertafel widget the remaining 4 Batch 1.4 skills (`skip5_forward/backward_zr100`, `skip10_forward/backward_zr100`) will reuse unchanged.

**Architecture:** BUILD_ORDER calls for a "Hundertertafel (100-field)" manipulative for these skills' field-visible levels. A fully-built, presentation-only `HundredChartWidget` (`math_app/lib/widgets/common/hundred_chart_widget.dart`) already exists and is already used by the diagnostic screen — its "sparse mode" (`visibleValues`/`highlightValue`/`queryValue`) renders exactly the "some numbers shown, one blanked as '?'" shape needed here, so this plan wraps it in a thin new custom_widget (`hundred_chart_skip`) rather than building a new grid from scratch. A new generator, `_generateHundredChartStep`, produces a `visible_count`-long visible run plus one query value via step arithmetic (mirroring `_generateSequenceGap`'s math, but with grid-shaped `display` fields and a single blank, matching `HundredChartWidget`'s single-query contract). Level 3 (symbolisch, "mental / field hidden") drops the grid entirely and reuses `sequence_gap`, exactly as Batch 1.4a did for the ZR20 pair.

**Tech Stack:** Flutter/Dart (`math_app/`), the v4 skill-spec JSON pipeline, the existing `HundredChartWidget` (reused, unmodified), the existing `_generateSequenceGap`/`SequenceGapWidget` (reused, unmodified for L3), Python sync/coverage scripts.

**Spec:** `docs/clean-room/v4/skills/BUILD_ORDER.md` Batch 1.4 (lines 38-39 of the 8-skill batch) + `docs/superpowers/specs/2026-09-15-exercise-plan-design.md` lines 170-175 (verbatim: "Manipulative: Hundertertafel (100-field)"; "Levels: 1) On the field (visible) -> 2) Mental (field hidden)"; "Example: '34, 36, 38, ...?' on the field, then without it.") + `docs/skill_spec_authoring_guide.md`. Precedent: `docs/superpowers/plans/2026-09-17-skip2-zr20.md` (sub-batch 1.4a, the `numberline_step`+`sequence_gap` half of the same construct family) and `docs/superpowers/plans/2026-09-17-quantify-count-zr10.md` (Batch 1.1, the last time this session built a genuinely new custom widget from scratch, for comparison — this one reuses an existing manipulative instead).

## Global Constraints

- German UI only.
- Every generated value stays in `[1, 100]` (the Hundertertafel's own range — `HundredChartWidget` renders cells `1..100`, unlike `numberline_step`'s ZR20 skills which could touch `0`). `_generateHundredChartStep` checks this explicitly and throws `SpecFormatException` rather than silently clamping, matching the `count_field`/`halving_mirror` idiom.
- `hundred_chart_skip`'s `step` must be one of `{2, 5, 10}` (the skip-counting family it serves), enforced by the generator itself.
- `error_taxonomy` is `miscount` + `other` only — `wrong_direction` does NOT apply here (it only fires for `problem.template == 'numberline_step'`; this skill's levels use `custom_widget`/`sequence_gap`), unlike sub-batch 1.4a's ZR20 pair which legitimately included it for its `numberline_step` levels.
- `hundred_chart_skip` evaluates via `_evaluateCustomWidget`'s default branch -> `_evaluateStringMatch`, exactly like `count_field`/`doubling_mirror`/`halving_mirror` — no new evaluator code.
- Never hand-edit `math_app/assets/skill_specs/*.json`.
- `domain` is `"A"`, `problem_count: 8` / `mastery.correct_of: 8` per level, matching every prior v4 spec.
- 44×44px touch-target floor: N/A here — `HundredChartWidget`'s cells are sized by `LayoutBuilder`/`constraints.maxWidth / 10` at `size: 320` default (32px cells), inherited unchanged from the diagnostic's existing usage; this plan does not touch that widget's sizing.
