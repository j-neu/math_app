# derive_via_10 family Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `derive_via_10_add_minus1`, `derive_via_10_add_plus1`, `derive_via_10_sub` (BUILD_ORDER.md Batch 1.10, construct `derive_10`) playable: three specific "derive an unknown fact via the power-of-10 anchor" strategies, reused from `S1.1 Fingerblitz`'s "Make (10-n)" family (`docs/superpowers/specs/2026-09-15-exercise-plan-design.md:382-388`).

**Architecture:** No new widget. All 3 skills reuse the existing generic `strategy_choice` template (`math_app/lib/practice/problem_generators.dart:892-974`, widget `math_app/lib/widgets/templates/strategy_choice_widget.dart`, evaluator `_evaluateStrategyChoice`) — the child solves `a op b`, types the numeric result, and taps the strategy label that names the method; both must be correct (confirmed by direct code read, not assumption). `strategy_choice`'s existing `_strategyNumbers` helper (`problem_generators.dart:980-1061`) already samples number pairs that genuinely exemplify `verdoppeln`/`fast_verdoppeln`/`ueber_die_zehn`, but none of its 3 cases match the specific derivations this batch needs — `ueber_die_zehn` sample any tens-crossing pair, not specifically "addend is 9" or "addend is 11", and there is no subtraction-via-10 case at all (the function's `op == '-'` branch (line 990) returns before the switch is ever reached, ignoring `strategy` entirely). This plan adds exactly 3 new strategy ids to `_strategyNumbers`'s switch — `ueber_zehn_minus1`, `ueber_zehn_plus1`, `ueber_zehn_sub` — each constraining the operands to the pattern its skill names, and narrows the `op == '-'` early-return guard so `ueber_zehn_sub` reaches the switch.

**Tech Stack:** Flutter/Dart (`math_app/`), the existing `strategy_choice` generator/widget/evaluator (widget and evaluator unmodified), the v4 skill-spec JSON pipeline, Python sync/coverage scripts.

**Spec:** `docs/clean-room/v4/skills/BUILD_ORDER.md` Batch 1.10 (lines 61-64) + `docs/superpowers/specs/2026-09-15-exercise-plan-design.md:382-388` (verbatim: "Archetype: Reused — S1.1 Fingerblitz's 'Make (10-n)' level directly covers this family"; "Levels: 1) 10-1 pattern (e.g. 6+9 via 6+10-1) → 2) 10+1 pattern (e.g. 7+11 via 7+10+1) → 3) subtraction via 10 (e.g. 15-8 via 15-10+2)").

**Judgment calls (must be flagged, not silently resolved):**

1. **The design doc's 3 "levels" are actually 3 separate skills, not 3 levels of one skill.** BUILD_ORDER.md lists `derive_via_10_add_minus1`, `derive_via_10_add_plus1`, `derive_via_10_sub` as 3 distinct skill ids under one construct (`derive_10`) — each independently needs its own v4-schema-mandatory 3 levels (`skill_spec.dart:334-344`). The design doc's "Levels: 1) ... → 2) ... → 3) ..." phrasing describes what distinguishes the 3 *skills* from each other (matching the pattern already established for `compare_quantity_difference`'s design-doc text, which named single-skill facts loosely too), not a single skill's EIS progression. Each skill's own 3 levels are range-escalations of its one fixed strategy (verified below).

2. **"Reused" does not mean the child sees a visual ten-frame decomposition.** `docs/superpowers/specs/2026-09-15-exercise-plan-design.md:385` says "Manipulative: Ten-frame / finger pattern anchored to 10", but `strategy_choice_widget.dart` (confirmed by direct read) shows only the bare equation and a strategy-name button — no ten-frame, no intermediate "6+10=16, 16-1=15" steps. The retired `S1.1 Fingerblitz` "Make (10-n)" level (`math_app/lib/widgets/finger_blitz_level3_widget.dart`, `FingerConstructionMode.subtractive`) turns out, on direct read, to be an unrelated finger-construction exercise ("start with 10 fingers, hide some to reach a target") — not an equation-decomposition UI at all. Building a new decomposition-visualizing widget would be a large, speculative departure with no existing precedent in this codebase's `strategy_choice` family (the only real prior spec for this template, the retired pre-v4 `docs/archive/skill_specs_pre_v4/v1/C4.1.json`, also used the bare self-report mechanic for `verdoppeln`/`ueber_die_zehn`). This plan reuses the existing self-report mechanic (numeric answer + tap-the-strategy-label) rather than inventing new UI, consistent with the "Reused" archetype's intent of minimal new code.

3. **`derive_via_10_add_minus1` fixes the *known* addend at exactly 9**, since "10-1" is only the *exact* decomposition when one addend is 9 (`a + 9 = a + 10 - 1`); similarly `derive_via_10_add_plus1` fixes the addend at exactly 11. `derive_via_10_sub` constrains the subtrahend to `[6, 9]` (close enough below 10 that "subtract 10, add back the difference" beats direct counting) and the minuend to `>= 11` (so the ten is actually crossed) — the design doc's own example (`15 - 8`) fits both constraints.

## Global Constraints

- German UI only; strategy `label_de` text states the method, e.g. `"über die Zehn (−1)"`.
- `domain` is `"C"` (Rechenstrategien, same subsection as `compare_quantity_difference`/`fingerblitz_quantity_zr10`, `docs/superpowers/specs/2026-09-15-exercise-plan-design.md:354-388`).
- Sums/differences stay within ZR20 (construct name `derive_10`, not `derive_100`; the design doc's own examples top out at 20).
- Every level uses `correct_strategy` fixed to its skill's one strategy id (never `"mixed"` — these are single-strategy skills, unlike the multi-strategy C4.1 precedent).
- `error_taxonomy` is `other` alone: `_evaluateStrategyChoice` requires both the numeric value AND the strategy label to match; no `_candidateErrorCode` special case applies to the `"value|strategy"` submission format.
- Never hand-edit `math_app/assets/skill_specs/*.json`.
- Existing `verdoppeln`/`fast_verdoppeln`/`ueber_die_zehn` strategy behavior and every existing `strategy_choice` test must be unchanged (regression check before Task 2 begins).

- [ ] **Step 2: Add the 3 new cases to the `switch (strategy)`**, inserted after the existing `'ueber_die_zehn'` case and before `default`:

```dart
case 'ueber_zehn_minus1':
  // "6+9 via 6+10-1": the known addend is always 9 -- the exact
  // decomposition a+9 = a+10-1 only holds for that specific addend.
  final a = gen.nextIntInRange(aLo, aHi);
  return (a, 9);

case 'ueber_zehn_plus1':
  // "7+11 via 7+10+1": the known addend is always 11.
  final a = gen.nextIntInRange(aLo, aHi);
  return (a, 11);

case 'ueber_zehn_sub':
  // "15-8 via 15-10+2": subtrahend close to (but below) 10 so
  // subtracting 10 then compensating beats direct counting; minuend
  // must be >= 11 so the ten is actually crossed.
  for (var attempts = 0; attempts < 300; attempts++) {
    final a = gen.nextIntInRange(max(aLo, 11), aHi);
    final b = gen.nextIntInRange(max(bLo, 6), min(bHi, 9));
    if (a - b >= 0) {
      return (a, b);
    }
  }
  throw SpecFormatException(
    'strategy_choice: "ueber_zehn_sub" cannot find a minuend >= 11 with '
    'a subtrahend in [6, 9] inside a_range/b_range',
  );
```

Update the function's doc comment (currently line 976-979) to mention all 3 new strategies.
