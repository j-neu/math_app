# count_forward_zr20 + count_forward_zr100 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `count_forward_zr20` and `count_forward_zr100` (BUILD_ORDER.md Batch 1.2, construct `count_forward`) playable — both are pure spec-authoring tasks: the existing generic `sequence_gap` template already implements the "type the missing numbers in a counting sequence" mechanic, so no new widget or generator code is written.

**Architecture:** Two skill spec JSONs, each with 3 levels (enaktiv/ikonisch/symbolisch), all using `template: "sequence_gap"` with `direction: "up"`, `step: 1` (this is sequential counting, not skip-counting) and per-level `start_range`/`length`/`gap_indices` that raise difficulty by widening the start range, adding gaps, and — for `count_forward_zr100` — biasing the start window so most sampled sequences cross a decade boundary (10s digit changes), per BUILD_ORDER's "decade-boundary starts emphasised" note. `count_forward_zr20` caps every value at 20 by construction (`start + (length-1)*step <= 20`); `count_forward_zr100` caps at 100 the same way. The shared `sequence_gap` generator (`math_app/lib/practice/problem_generators.dart:259-327`) and `SequenceGapWidget` (`math_app/lib/widgets/templates/sequence_gap_widget.dart`) are unchanged — only the assertion tests proving the two real specs parse and generate in-range problems are new.

**Tech Stack:** Flutter/Dart (`math_app/`), the v4 skill-spec JSON pipeline (`SkillSpec`, `SkillSpecStore`, `problem_generators.dart`'s existing `_generateSequenceGap`, `template_registry.dart`'s existing `SequenceGapWidget` wiring), Python sync/coverage scripts.

**Spec:** `docs/clean-room/v4/skills/BUILD_ORDER.md` Batch 1.2 (lines 26-28) + `docs/superpowers/specs/2026-09-15-exercise-plan-design.md` lines 94-107 (level descriptions: zr20 "Start at 1 → Start at any number 1-15, count 5 more"; zr100 "Start mid-decade (e.g. 34) → Start just before a decade boundary (e.g. 29, 49, 69)") + `docs/skill_spec_authoring_guide.md`. Precedent: `docs/superpowers/plans/2026-09-17-quantify-count-zr10.md` (Batch 1.1, full pipeline with a new custom widget) and `docs/clean-room/v4/skills/specs/double_zr10.json`/`quantify_count_zr10.json` (spec JSON shape, provenance citation style).

## Global Constraints

- German UI only — every user-facing string (`prompt_de`, `level_titles_de`) is German.
- `count_forward_zr20` is capped at ZR20: every generated sequence value must be in `[1, 20]`. `count_forward_zr100` is capped at ZR100: every value in `[1, 100]`.
- `sequence_gap`'s only built-in safety net is the *global* `_maxZR = 100` clamp (`problem_generators.dart:36`) — it has no per-skill ZR20 ceiling. The ZR20 cap is enforced purely by choosing `start_range`/`length` so `start + (length-1)*step <= 20` for every possible sampled start; this plan's params are already checked against that (see each task).
- Direction is always `"up"` and step is always `1` for both skills — `count_forward` is sequential counting, not skip-counting (skip-counting is the separate Batch 1.4) and not backward counting (that's `count_backward_zr20`/`zr100`, a separate "New" skill elsewhere in BUILD_ORDER).
- Only use `error_taxonomy` codes `TemplateEvaluator._candidateErrorCode` can actually emit for `sequence_gap`: the undirected `"miscount"` (only fires when a level's `expected` has exactly 1 value, i.e. single-gap problems) plus the mandatory `"other"` fallback — never `"wrong_direction"` (only fires for `numberline_step`, `template_evaluator.dart:391-395`) or any `off_by_one_*` code, the exact mistake `double_zr10`/`halve_zr10` shipped with per the authoring guide's warning.
- Never hand-edit `math_app/assets/skill_specs/*.json` — it is generated by `scripts/sync_skill_specs.py` from `docs/clean-room/v4/skills/specs/`.
- `domain` is `"A"` for both (Domain A — Zahlbegriff, "Sequencing forward/backward" subsection, `docs/superpowers/specs/2026-09-15-exercise-plan-design.md:76,94`), matching `quantify_count_zr10` (also domain A) rather than `double_zr10`/`halve_zr10` (domain C).
- `problem_count: 8` / `mastery.correct_of: 8` per level, matching the precedent set by all 3 already-shipped v4 specs (not the generic 10-problem curve in `DIFFICULTY_CURVE.md`, which describes hand-authored difficulty ordering that doesn't apply to this seeded-random-sampling generator).

Decade-crossing rationale (why these specific windows, not just "wide enough"): a run of `length` consecutive integers starting at `start` avoids every multiple of 10 iff `(start mod 10) + (length-1) <= 9`, i.e. `start mod 10 <= 10 - length`. For L3 (`length=8`), that's `start mod 10 <= 2` — roughly 80% of samples in `[19,89]` cross. This matches BUILD_ORDER's "decade-boundary starts emphasised" without needing new generator logic (the generator only supports a single contiguous `start_range`, not modular/periodic sampling).

    test('real count_forward_zr20 generates sequences within [1, 20]', () {
      final s = _realSpec('count_forward_zr20');
      for (var level = 1; level <= 3; level++) {
        for (var seed = 0; seed < 100; seed++) {
          for (final p in generateProblems(spec: s, level: level, seed: seed)) {
            expect(p.template, 'sequence_gap');
            final values = (p.display['values'] as List).cast<int>();
            for (final v in values) {
              expect(v, inInclusiveRange(1, 20));
            }
            // Strictly increasing by 1 (direction up, step 1).
            for (var i = 1; i < values.length; i++) {
              expect(values[i], values[i - 1] + 1);
            }
            final gapIndices = (p.display['gap_indices'] as List).cast<int>();
            expect(p.expected,
                gapIndices.map((i) => values[i].toString()).toList());
          }
        }
      }
    });

    test('real count_forward_zr100 generates sequences within [1, 100]', () {
      final s = _realSpec('count_forward_zr100');
      for (var level = 1; level <= 3; level++) {
        for (var seed = 0; seed < 100; seed++) {
          for (final p in generateProblems(spec: s, level: level, seed: seed)) {
            expect(p.template, 'sequence_gap');
            final values = (p.display['values'] as List).cast<int>();
            for (final v in values) {
              expect(v, inInclusiveRange(1, 100));
            }
            for (var i = 1; i < values.length; i++) {
              expect(values[i], values[i - 1] + 1);

            expect(p.expected,

    test(
        'real count_forward_zr100 level 2/3 sequences cross a decade '
        'boundary most of the time (decade-boundary emphasis)', () {
      final s = _realSpec('count_forward_zr100');
      for (final level in [2, 3]) {
        var crossings = 0;
        var total = 0;
        for (var seed = 0; seed < 200; seed++) {
          for (final p in generateProblems(spec: s, level: level, seed: seed)) {
            total++;
            final values = (p.display['values'] as List).cast<int>();
            final crosses = values
                .any((v) => v % 10 == 0 && v != values.first);
            if (crosses) crossings++;
          }
        }
        expect(total, greaterThan(0));
        expect(crossings / total, greaterThan(0.5),
            reason: 'level $level should cross a decade boundary in most '
                'generated sequences, per BUILD_ORDER\'s decade-boundary '
                'emphasis note');
      }
    });
