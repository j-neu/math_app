# skip2_forward_zr20 + skip2_backward_zr20 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `skip2_forward_zr20` and `skip2_backward_zr20` (BUILD_ORDER.md Batch 1.4, the ZR20 half — construct `skip2_forward`/`skip2_backward`) playable, as sub-batch 1.4a of the larger 8-skill Batch 1.4. Zero new Dart code: level 1/2 reuse the existing `numberline_step` template (built explicitly for stepwise 1/2/5/10 skip-counting, per its own doc comment), level 3 reuses `sequence_gap` (proven 4x already this session).

**Architecture:** Each skill has 3 levels. Levels 1-2 use `numberline_step`: the child taps every number from a sampled `start` to a fixed `target`, `step: 2`, in the skill's direction. `_generateNumberlineStep`'s existing congruence filter (only starts with `start % step == target % step` are sampled) is repurposed as a *content* lever, not just a safety check: choosing an **even** `target` (20 for forward, 0 for backward) forces every level-1 start to be even ("forward from [near] 0" / mirrored for backward); choosing an **odd** `target` (19 forward, 1 backward) forces every level-2 start to be odd ("from an odd start"), exactly matching the design doc's two-level split without any new generator logic. Level 3 drops the visual number line entirely and uses `sequence_gap` (`length: 4`, one trailing gap) to match the design doc's own written-pattern examples ("2, 4, 6, ...?" / "20, 18, 16, ...?") at the hardest, most symbolic tier.

**Tech Stack:** Flutter/Dart (`math_app/`), the v4 skill-spec JSON pipeline (existing, unmodified `_generateNumberlineStep` and `_generateSequenceGap`, `NumberlineStepWidget` and `SequenceGapWidget`), Python sync/coverage scripts.

**Spec:** `docs/clean-room/v4/skills/BUILD_ORDER.md` Batch 1.4 (lines 35-43, this plan covers only lines 36-37) + `docs/superpowers/specs/2026-09-15-exercise-plan-design.md` lines 162-168 (verbatim: "Levels: 1) Forward from 0 -> 2) Forward from an odd start -> 3) (backward variant) same, reverse"; "Example: '2, 4, 6, ...?' / backward: '20, 18, 16, ...?'") + `docs/skill_spec_authoring_guide.md`. Precedent: `docs/superpowers/plans/2026-09-17-successor-predecessor-zr20-decade.md` (Batch 1.3, most recent `sequence_gap`-only plan) — this plan is the first to also use `numberline_step`.

**Scope note:** BUILD_ORDER's Batch 1.4 has 8 skills total. The remaining 6 (`skip2/5/10_forward/backward_zr100`) need a new wrapper widget around the already-existing `HundredChartWidget` (`math_app/lib/widgets/common/hundred_chart_widget.dart`, confirmed reusable, already used by the diagnostic) for their "field-visible" levels — real new Dart code, unlike this sub-batch — and are deliberately split into a separate plan/worktree (sub-batch 1.4b) rather than bundled here, since they're a different shape of work.

- Every generated value stays in `[0, 20]` (ZR20) — both skills' `range` param is `[0, 20]` throughout, and `numberline_step`'s own bounds checking (`target` inside `range`, congruent `start` inside `start_range` and `onLine`) enforces this; `sequence_gap`'s level-3 params are hand-checked to stay in range (see Task 1/2 bound checks).
- `step` for `numberline_step` must be one of `{1, 2, 5, 10}` (enforced by the generator itself, `problem_generators.dart:1462-1466`) — `2` here is valid.

It will simply never fire on level 3 (`sequence_gap`'s `_evaluateJoined` never calls `_candidateErrorCode`), which is fine — an error code omitted from every problem it's ever shown for isn't a defect, unlike adding a code no template can ever emit (the mistake the authoring guide warns against).

- `domain` is `"A"` (Zahlbegriff, "Sequencing forward/backward" subsection, `docs/superpowers/specs/2026-09-15-exercise-plan-design.md:76,94,162`).

## Self-Review Notes

- **Spec coverage:** both skills fully covered. The authoring guide's generic-template check (step 2) considered `numberline_step` vs `sequence_gap` explicitly and used both, per-level, rather than picking one for the whole skill — a first for this session, justified by wanting a genuine EIS progression (enaktiv/ikonisch = interactive tap-strip via `numberline_step`, symbolisch = pure typed recall via `sequence_gap`) rather than the same widget at every level.
- **Placeholder scan:** none.
- **Type consistency:** `numberline_step` tests read `p.display['start']`/`['target']`/`['step']`/`['direction']` as their declared types (`int`, `int`, `int`, `String`) matching `_generateNumberlineStep`'s `display` map exactly (`problem_generators.dart:1508-1514`); `sequence_gap` tests match Batch 1.2/1.3's established `(p.display['values'] as List).cast<int>()` style.
- **Design deviation flagged, not silently made:** `numberline_step`'s congruence filter being repurposed as a parity-forcing content lever (choosing an odd `target` to force all sampled starts odd) is a non-obvious technique specific to this generator; documented here and in the JSON's own level structure so a future author extending this pattern (e.g. for the zr100 mental levels in sub-batch 1.4b) can reuse it deliberately rather than rediscovering it.
